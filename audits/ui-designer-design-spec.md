## 2. Design principles

1. **Tokens, not literals.** Every colour, size and spacing the views use lives in
   `rdm-gui/src/theme/`; a unit test fails the build if a view reintroduces a colour literal.
2. **Contrast is a contract, not an opinion.** Role→surface pairs and their minimum WCAG ratios
   are data (`theme/contrast.rs::CONTRACT`) and are asserted for both themes.
3. **Colour is never the only signal.** Every state also carries a glyph and a text label
   (WCAG 1.4.1); selection carries an accent bar in addition to the fill.
4. **The keyboard is a first-class input.** Selection, details, refresh, search and closing
   overlays are reachable without a mouse (WCAG 2.1.1).
5. **Density with air.** The table stays a table: fixed column rhythm, one flexible FILE column,
   consistent 42 px rows, 8 px padding — identical in header and body.
6. **Preserve behaviour.** Token adoption kept the previously shipped numbers; visible changes are
   deliberate, listed in §10.

**Semantics.** `accent` is the single interactive blue: Running transfers, focus rings, the
selected-row accent bar, primary buttons and links. `success` = Completed, `merging` = assembling
chunks, `warning` = Queued/waiting, `interrupted` = resumable failure, `danger` = Failed and every
destructive action, `text_muted` = Paused/Cancelled, ids, metadata, hints and timestamps.

**Why these values.** Every role reaches ≥ 4.5:1 (WCAG AA, SC 1.4.3) on **all eight surfaces it may
be painted on**, in both themes; the worst pair in the whole system is 5.01:1. The focus/accent
colour reaches ≥ 5.28:1 everywhere, comfortably above the 3:1 required by SC 1.4.11.

**Grid.** The table is a fixed-rhythm grid: one flexible column (FILE) plus fixed columns whose
widths adapt by *dropping optional columns* in a defined priority order (ADDED → SPEED → ETA), then
compressing the progress bar, then scaling the fixed columns proportionally (floor 25 %), always
keeping FILE ≥ 80 px. The header and every body row share **one** width computation per frame, so a
header can never advertise a column the rows dropped.

## 6. Responsive matrix

| Width | Table | Toolbar | Sidebars / panels |
| --- | --- | --- | --- |
| ≥ 1024 (wide) | all 10 columns, FILE ≥ 140 px | actions + search + filters + keyboard hint | sidebars up to 400 px each (40 % cap) |
| 720–1024 (regular) | optional columns dropped in order ADDED → SPEED → ETA | keyboard hint hidden when the row would wrap | sidebars to 40 % of the window |
| 520–720 (compact) | narrower PROGRESS, proportional down-scale of fixed columns | hint text hidden (saves a row in small windows) | sidebars floor at 260 px |
| 300–520 (minimum) | FILE pinned at its 80 px floor, cells truncate with `…` | search + filters wrap onto further rows | modals (500×360 min) stay usable |

Invariants are unit-tested: `columns_never_exceed_the_available_width` (300 → 1600 px),
`narrow_panels_drop_optional_columns_before_the_file_name`,
`optional_columns_are_dropped_in_priority_order`, `wide_panels_keep_every_column`.

## 7. Interaction, focus and semantics

**Keyboard map** (implemented in `app.rs::handle_shortcuts`, active only while no text field has
focus, so typing is never hijacked):

| Key | Action |
| --- | --- |
| ↑ / ↓ | move the selection through the **visible** rows (respects search + state filter) |
| Enter | open the details modal for the selected download (same as double-click) |
| Esc | close the top-most overlay: New download → Remove confirmation → details → footer panel → both sidebars |
| Ctrl/⌘ + F | focus the search box |
| F5 | re-read the metadata database (same as ⟳ Refresh) |
| Tab / Shift+Tab | egui's native focus order across every control |

**Focus visibility.** The focus/accent colour is token-driven (`accent`, ≥ 5.28:1 on all surfaces —
SC 1.4.11); the selected row also gets a 3 px accent bar, so a *selected* row and a *hovered* row
are distinguishable without relying on fill colour alone.

**Accessible names.** Every icon-only control carries a tooltip that states its action and the CLI
equivalent (⏸ Pause (rdm pause), ⏹ Cancel, ▶ Resume, ⟲ Restart, 📂 Open folder, 🗑 Remove, ✕ Close /
Clear / Drop). Every hint, label and table header is real text, so screen readers get the same
information as sighted users.

**Semantics of the table.** Rows are one large click target (select) with double-click (details);
the row tooltip exposes the full URL and output path that a narrow column may truncate.

## 10. Intentional visible changes (everything else is behaviour-preserving)

1. **State colours retuned for contrast** (see §3): e.g. Failed is `#FF8A8A` on dark instead of
   `#DC2626`, Completed is `#0F6B33` on light instead of `#16A34A`. Required: the old values failed
   AA on every surface (worst 1.43:1).
2. **Row surfaces defined by tokens**: hover `#3A3A3A` (dark) / `#E6E6E6` (light) and selection
   `#1E3A5F` / `#D8EBFF` now come from the palette instead of egui's defaults, because they are the
   backgrounds the contract measures.
3. **Small text 11 px** instead of egui's 9 px — the metadata columns and log lines were below a
   comfortable reading size.
4. **Header/rows share one column geometry** — previously the rows' budget was computed from a
   2 px narrower rect than the header's, so at a boundary width the header could show a column the
   rows had dropped.
5. **New keyboard support** (§7), purely additive.
6. **Table header labels are muted**, values in the SIZE column are primary text — a deliberate
   hierarchy decision replacing “whatever egui's default text colour was”.
